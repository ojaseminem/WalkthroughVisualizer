Tag the art.
The experience
builds itself.

One WebGL runtime that reads a correctly tagged 3D scene and produces a finished walkthrough — navigation, UI, data panels, guided tours, wayfinding — with no bespoke code per project.

An apartment tower, a hospital wing, a mall, a plant. Same engine, same pipeline, different tags.

00

What we are actually building

Not a walkthrough. A walkthrough factory. The value is in the contract between the art department and the runtime: an artist tags a node wv.type=POI with a label and a body of copy, and the runtime — without being told this project exists — spawns a hotspot, adds it to the room directory, wires it into the minimap, makes it linkable by URL, and logs a view event.

Three properties decide whether this succeeds:

  • The tag schema is the product. If it is expressive enough for a hospital and simple enough for an interior artist, everything downstream is easy. If it is wrong, every project needs code again.
  • Authoring must be enforced, not documented. A Blender/Max add-on that writes tags plus a validator that fails a build loudly beats a PDF nobody reads.
  • The runtime must be boring and fast. Baked lighting, compressed assets, a hard frame budget on a mid-range Android. Nothing about the tech should be visible to a client walking their unbuilt lobby.

03

Architecture — five layers

Each layer talks to the next through a file format, never a function call. That is what makes the art side and the runtime side independently replaceable.

Runtime systems in L3

  • Movement: first-person walk (capsule + gravity, clamped to navmesh), orbit/dollhouse, click-to-teleport, guided spline tour, top-down plan.
  • Spatial: level/floor manager, portal culling from the baked graph, A→B pathfinding on the nav graph (this is what makes hospital wayfinding free).
  • Presentation: baked lightmaps + probes, sun study, material variant sets, measurement, annotations, screenshot, URL-state bookmarking.
04

The tagging contract

Everything hangs on this. Tags live in glTF node.extras under a wv namespace, authored by the add-on and checked by the validator. Draft shape:

// node.extras on a reception desk mesh
{
  "wv": {
    "type": "POI",
    "id": "lobby.reception",
    "label": "Reception",
    "level": "L00",
    "zone": "lobby",
    "tags": ["public", "staffed"],
    "panel": {
      "body": "Visitor check-in, 24h.",
      "media": ["img/reception-01.jpg"]
    },
    "anchor": { "offset": [0, 1.2, 0] }
  }
}

Node types the runtime recognises

TypeAuthored asRuntime builds
NAV_FLOORFlat walkable mesh, invisibleNavmesh + walk clamp + teleport targets
NAV_BLOCKSimple collision volumeCarved holes in the navmesh
PORTALQuad in a doorwayVisibility graph, room-to-room culling
ZONEBox volume + labelRoom directory entry, minimap region, "you are in"
POIEmpty or mesh + copyHotspot pin, info panel, deep link, analytics event
VARIANT_SETSibling meshes/materialsFinish switcher in the UI
CAM_TOUROrdered camera emptiesGuided tour player with chapters
DESTEmpty + directory dataWayfinding search target and route endpoint

Anything untagged renders as plain geometry — so a scene degrades gracefully instead of erroring, and an artist can tag incrementally.

05

Verticals are config, not forks

A preset is a JSON file that turns systems on, orders UI panels, and sets copy. Adding "mall" or "plant" later must never mean a new codebase.

Archviz preset

Sell an unbuilt space

  • Walk / dollhouse / floor plan triad
  • Finish & furniture variant switcher
  • Sun study with time-of-day scrub
  • Area & dimension measurement
  • Unit schedule and availability overlay
  • Shareable bookmarked viewpoints

Hospital preset

Orient a stranger under stress

  • Search a department, doctor, or entrance
  • A→B route drawn on the floor, level-aware
  • Step-by-step directions with landmarks
  • Accessible-route toggle
  • Department directory and colour legend
  • Kiosk mode with idle reset

Both read the same scene.glb. The difference is which tag types the preset cares about.

07

Open decisions — I need seven answers

These change the architecture, not the polish. My recommendation is noted on each; override freely.

1. Who authors the art?

If it is only you and TGW artists, the tag schema can be terse and the add-on thin. If clients or outsourced studios deliver scenes, the validator and naming-convention fallback become first-class work.

rec: assume external artists — build the validator early, it is cheap now and brutal later

2. Lighting: baked or real-time?

Baked lightmaps out of Blender Cycles give UE-adjacent quality at mobile frame rates but freeze the time of day per bake. Real-time keeps sun study fully dynamic and costs fidelity.

rec: baked as the default, with 2–3 baked time-of-day sets and a real-time toggle for the sun-study panel

3. What is the target device floor?

This sets every budget in the project. A mid-range Android at 30fps is a very different scene than a desktop at 60.

rec: mid-range Android 30fps / desktop 60fps, enforced by an automated perf test from M2 onward

4. Do we own the DCC, or accept anything?

Blender-first lets me ship an add-on immediately. 3ds Max is where most Indian archviz studios actually work, and would need a second exporter.

rec: Blender add-on first, plus a naming-convention path so any DCC that exports glTF still works

5. Runtime stack — plain three.js or React Three Fiber?

Plain three.js keeps the core framework-agnostic and embeddable anywhere. R3F speeds UI work but couples the engine to React.

rec: plain three.js core, React only in the UI layer, talking over an event bus

6. Where does content live?

Fully static (S3/Cloudflare, one folder per project) is simplest and cheapest. A small backend unlocks per-client dashboards, gated links, and analytics.

rec: static for M1–M5; design project.json so a backend can serve it later without a runtime change

7. What is the first real scene I model?

I will build the demo models here. A 2BHK apartment is the fastest path to a showable archviz demo; a hospital wing proves the harder wayfinding case earlier.

rec: 2BHK apartment for M1, hospital wing at M5 — unless you have a live client scene worth targeting
